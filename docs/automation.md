# 批量收藏与缓存：自动化可行性评估

结论先说：**在 iPad 上，用豆包或任何第三方工具「批量打开 + 加入收藏夹 + 启动缓存」不可行，
也不该作为主方案。** 可行的是「网站生成有序清单 + 唤起 App + 用户逐条确认」，
这正是 `#/offline` 页面在做的事。

---

## 1. 逐条回答

### 1.1 豆包普通 iPad App 能不能跨 App 操作 B 站

不能。

- 普通豆包 App 是对话式助手，没有 iOS 上的「无障碍点击其他 App 界面」权限；
  iPadOS 也不向第三方 App 开放系统级的跨应用自动化。
- 官方说明里的「豆包手机助手」是**与特定手机厂商合作的系统级能力**，
  依托那台手机的系统和硬件，不是 iPadOS 上的通用助手。
- 即使某天出现「能代点」的手机助手，也解决不了 iPad 上的问题：它不在 iPad 上。

### 1.2 有没有可用的官方连接、API、插件或快捷指令

逐项核对的结果：

| 途径 | 现状 | 能否完成目标 |
| --- | --- | --- |
| 哔哩哔哩开放平台 | 面向合作方的开放接口，**没有面向个人开发者的「写收藏夹 / 触发缓存」能力** | 否 |
| 哔哩哔哩网页端接口 | 内部接口，需要登录 Cookie 与风控参数，非公开契约 | 否（且违规风险） |
| 系统「快捷指令」 | 能打开 URL / App、能读写剪贴板，**不能点击 App 内部按钮** | 只能做前半段 |
| 豆包 / 其他 AI 连接器 | 当前没有哔哩哔哩或豆包的直接连接可用来操作收藏与缓存 | 否 |
| 第三方「自动下载收藏夹」工具 | 普遍要求导入账号 Cookie，部分直接抓流 | 否（凭据与版权风险） |

「快捷指令」能做到的极限是：从本站复制一条链接 → 打开 B 站 App → 你手动点收藏和缓存。
这比在本页直接点「B 站」按钮更绕，没有实际收益。

### 1.3 哪些能自动化，哪些必须本人确认

| 环节 | 能否自动化 | 说明 |
| --- | --- | --- |
| 排出学习顺序 | 能 | 本站按 域 → 专题 → 小节 现推，不依赖收藏夹排序 |
| 生成待办清单 | 能 | 「复制待缓存清单」一键生成纯文本 |
| 定位下一条没缓存的 | 能 | 「打开下一条未缓存」，滚动高亮 |
| 唤起 B 站 App 到指定视频 | 能（尽力） | `bilibili://video/BVxxx`，失败自动退回网页版 |
| 加入指定收藏夹 | **不能** | 必须在 App 内点，且收藏夹本身要在 App 里先建好 |
| 选择清晰度并开始缓存 | **不能** | 弹层交互，涉及账号权益判断 |
| 确认缓存完成 | **不能** | 只能在「离线缓存」里看，或回到本站手动勾 |

注意最后三项不只是「技术上难」，而是**本来就应该由人确认**：
缓存清晰度关系到账号权益与存储空间，误点一次就是几百 MB。

### 1.4 会不会碰到 Cookie、验证码、风控或平台规则

会，而且是这类方案失败的常态：

- **凭据**：任何「帮你批量收藏/下载」的第三方工具，第一步几乎都是要 Cookie 或扫码登录。
  这等于把账号完全交出去，风险远大于省下的几十次点击。
- **验证码与二次确认**：异地登录、频繁操作会触发滑块或短信验证，脚本直接卡死。
- **风控**：短时间大量收藏/请求会被限流，轻则失败重试，重则账号受限。
- **平台规则**：绕过缓存限制抓流、批量模拟操作，通常违反用户协议；
  视频版权归原作者，转存与再分发也有风险。

结论：即使技术上能跑通，也是**用账号安全和合规风险换一点便利**，不划算。

### 1.5 自动化不可靠时的优先方案

已经实现，也就是本站的两段式分工：

```
网站（离线可用）                      B 站官方 App
─────────────                      ─────────────
按学习顺序列出 32 条        →        逐条加入 ICT-01～04 收藏夹
标出还差哪几条              →        点「缓存」选 720P
一键唤起下一条              →        在「离线缓存」里确认
勾「已缓存 / 已看完」       ←        看完回来打勾
```

网站负责**顺序、清单、进度**；App 负责**合法缓存**。
32 条视频按这个流程走一遍，大约 20～30 分钟操作，一次性投入。

## 2. 如果还想再省一点力

按性价比排序，这三件事值得做，且都不碰账号凭据：

1. **先在 App 里建好 4 个收藏夹**（ICT-01～04），之后每条只需「收藏 → 选夹 → 缓存」三步。
2. **用「复制待缓存清单」**生成带序号的文本，粘到 iPad 备忘录，照着勾；
   比在 App 里来回找快得多，也不会漏。
3. **一次只处理一个专题**（例如今晚只做 oe-01、oe-02 共 16 条），
   避免连续操作触发风控，也方便中途核对。

不建议做的事：

- 把 Cookie / 扫码凭据交给任何下载站或「AI 工具」；
- 用解析站抓流（既违规又有版权问题）；
- 为了「全自动」去装描述文件、越狱插件或来路不明的快捷指令。

## 3. 什么时候可以重新评估

如果以后出现下面任一情况，这份结论值得更新：

- 哔哩哔哩开放平台推出面向个人的收藏夹写接口（需 OAuth 授权、有配额）；
- iPadOS 开放跨 App 的受控自动化（类似 Android 的无障碍服务）；
- 豆包推出 iPadOS 上可授权的系统级助手能力。

在这些发生之前，「网站清单 + 官方 App 缓存」就是最稳的方案。
